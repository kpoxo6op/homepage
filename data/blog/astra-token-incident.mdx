In my [last post](/blog/hey-gi/), I joked that perhaps I would put GPT-6 Astra to work on the next version of my wake-word model.

The definition tooltip still describes Astra as a hypothetical future OpenAI model. Three weeks later, it exists, I got access, and I managed to burn through my usage hard enough to investigate what happened.

Good timing.

## Giving Astra the cluster

People who got early access to Astra were posting impressive results. OpenAI describes it as its most intelligent model yet, especially good at long tasks involving code, browsers, and other software.

I was impressed too. So I gave it something appropriately horrible.

I have a home Kubernetes cluster called Soyspray. I started building it several years ago while learning Kubernetes, Ansible, Argo CD, and most of the other technology around it.

The repository works, but it grew rather than being designed. It contains new systems, old systems, repaired systems, half-replaced systems, and various pieces of debris that I planned to clean up later.

Later had finally arrived.

I pointed Astra at a long handover and told it to continue the cluster cleanup. At different times, I also tried Extra High and Ultra reasoning because the strongest model obviously needed the biggest possible brain setting.

Then I went for a walk with a friend.

When I checked the computer later, Astra had done real work. It had inspected the cluster, changed code, run tests, checked the result, and written explanations about everything.

It had also eaten my usage limit.

I did not think much about it. This was a large task, and I had a saved usage reset. I used the reset, started another iteration, and probably went for another walk.

Eventually that limit disappeared too.

The amount of work was useful, but it did not feel like two usage limits of magic. So I returned to the computer and tried to understand what I had actually bought with all those tokens.

## One useful post on X

I opened X and searched through the deserved praise for Astra.

Among it, one person said he was switching back to GPT-5.6 Sol as his main executor. He would use Astra only as an advisor because he was not a billionaire or a privileged reviewer who could run it constantly.

I did not save the post, so this is my paraphrase. But the idea was clear:

Sol does the work. Astra makes the difficult decisions.

My guess is that some spectacular early Astra examples also used much tighter tasks than mine. Perhaps some reviewers did not need to care about their personal limits. I cannot prove either explanation.

What I could do was test the workflow on my own cluster.

## Sol executes, Astra advises

I opened a fresh Codex CLI session with GPT-5.6 Sol at Medium reasoning.

The task was [Soyspray issue #309](https://github.com/kpoxo6op/soyspray/issues/309). It involved moving the existing Prometheus monitoring stack under native Argo CD ownership without losing metrics, storage, credentials, or access.

This was not only a file-moving exercise. The cluster did not have enough backup and restore evidence to make the live ownership change safely.

Sol owned the investigation, implementation, tests, Git history, and pull request. I configured Astra as a read-only advisor for the difficult architecture and safety decisions.

The result was [draft PR #310](https://github.com/kpoxo6op/soyspray/pull/310), with ten organized commits. All local checks and GitHub checks passed.

The agent also stopped at the correct safety boundary. It did not deploy anything. The pull request clearly says which backup, restore, and storage checks must exist before deployment.

That was almost exactly what I wanted.

## What the logs showed

I asked Astra itself to help analyze the earlier runs. I then compared the local Codex session logs with OpenAI's current credit rates.

These numbers are credit-equivalent estimates. They are useful for comparing runs, but they are not an invoice from my account.

| Run                                      |    Raw tokens | Credit equivalent |
| ---------------------------------------- | ------------: | ----------------: |
| Earlier Astra-only cluster session       | 18.50 million |             558.8 |
| Issue #309 with Sol and an Astra advisor | 16.61 million |             295.2 |

The mixed run used only 10.2% fewer raw tokens, but approximately 47.2% fewer credits.

Astra handled 10.5% of the mixed run's raw tokens. That small part still represented 31.5% of the estimated credits.

This matches [OpenAI's current pricing](https://learn.chatgpt.com/docs/pricing). Astra costs 2.5 times as many credits as Sol for uncached input, cached input, and output tokens.

There was another interesting number. Approximately 96.8% of the mixed run's input was cached.

The agents were not writing sixteen million tokens of new prose. They were repeatedly carrying a large project context through many model responses. Caching made that much cheaper, but not free.

The Sol executor produced about one hundred model responses. The Astra advisor thread added six logical turns and twenty-two model responses. Some advisor turns only confirmed that no further change was needed.

Even the advisor had become an agent that advised about its own advice.

OpenAI's [subagent documentation](https://learn.chatgpt.com/docs/agent-configuration/subagents) says this directly: every subagent performs its own model and tool work, so a subagent workflow uses more tokens.

The same documentation says Medium is a balanced default. High is suitable for reviewers that must trace complex logic. Higher reasoning levels increase token use.

OpenAI's [Astra guidance](https://developers.openai.com/api/docs/guides/latest-model) also says Astra tends to produce detailed responses and can run broader tests than small tasks require.

So my first reaction was not quite correct. I wanted OpenAI to fix its shit, but my logs did not show an unusual Astra token leak.

They showed a costly model doing too much ordinary executor work inside a very long session.

Also, the Astra-only session I measured was running at Medium. I cannot even blame all of it on Ultra.

## What I changed

Sol is now my default executor at Medium reasoning.

Astra remains available at High reasoning as a read-only advisor. Sol must give it one compact design packet before a consequential change and one combined review packet before delivery.

Astra does not repeat investigation or tests unless the supplied evidence is missing or inconsistent. A clear approval ends the review. Sol does not ask Astra to confirm its own confirmation.

The important part is not only selecting a cheaper model. The instructions must stop both agents from talking to each other forever.

If you want Codex to analyze your own runs, you can give it this:

```text
Compare my latest Astra-heavy Codex session with the closest similar Sol
session. Read the local rollout JSONL logs. Separate uncached input, cached
input, and output tokens. Apply the current official Codex credit rates.

Show the number of model responses, the advisor's share, and the estimated
credits for each run. Separate measured facts from speculation.

Then propose the smallest AGENTS.md and agent TOML changes that keep Sol as
the executor and Astra as a read-only advisor. Do not edit anything until I
approve.
```

Times are changing very fast.

I asked my home computer to analyze the AI sessions it had run. Then I went for a walk and continued the same conversation from my phone through Codex Remote while the computer at home did the work.
